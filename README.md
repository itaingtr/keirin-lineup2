# keirin-lineup2

公開先は https://itaingtr.github.io/keirin-lineup2/ です。GPTログインは不要で、`line20261025.html` のような日付ページも同じ場所に置きます。トップと最新日付ページのHTMLは同一です。

11月2日以降は、赤「映像」・緑「結果」・青「ライブ」の順です。映像とライブは楽天Kドリームスへ移動し、結果も当面は楽天の該当レースを開きます。映像のパソコン用750×470ウィンドウとスマートフォンの同じタブでの移動は維持します。

車番を押すと、その選手の調子を1→2→3→4→5→1と変更できます。5が一番よい評価で、未評価は空欄です。合言葉で一度ログインすると同じブラウザでログイン状態を保持し、投稿と調子の入力ができます。評価は皆で共有し、今日の数字を今場所成績の下に表示します。翌日からは選手IDとレースIDで照合し、以前の着順の横に緑の数字を表示します。車番の変更には影響されません。

評価は既存の投稿用保存先へ専用キーで小さな記録を追記します。連打はまとめて保存し、過去の記録・通常のコメントは上書きも削除もしません。読み直した時と表示中の約30秒ごとに共有値を確認します。評価のために翌日分を複製保存することもありません。

10月30日以降の予想印は、車番・選手名・期別を照合した楽天Kドリームスの掲載印です。レース名のリンクも楽天へ移動します。画面の旧サービス名とAI印の補助表示を外し、既存の選手成績・並び・オッズの取得元記録は維持します。印は表示用の項目だけを実行別に追記し、翌日分の自動作成にも引き継ぎます。

WINTICKETの公開S級出走表、並び、AI印、前日までの今場所成績と二車単の保存値を表示します。楽天Kドリームスの値を取得元だけ付け替えて使うことはありません。映像・ライブ・着順は同じタブの公式ページへ移動し、選手選択の `playerIds` を維持します。

`.github/workflows/update.yml` が承認不要で実行します。日本時間21:00・23:30に翌日分の出走表を取得・検証して公開し、当日の08:00〜20:30は15分間隔（08:00、08:15、…、20:30の1日51回）でオッズを取得します。取得できた最新オッズは表示用の最新値に上書き反映します。GitHubの実行開始は遅れる場合があり、予定された最終20:30の実行は遅延が1時間以内なら受け付けます。手動実行の `publish` は保存済みデータの公開、`cards` は翌日分の取得、`odds` は当日分の取得です。

一時的な取得元の404・サーバーエラー・通信エラーは2秒後・5秒後に再試行し、最大3回で止めます。出走選手未確定・検証失敗なら公開中のページを維持し、夜の次回取得で確認します。23:30の起動が日付をまたいでも、取得対象をさらに翌日へずらしません。

表示用データは同じリポジトリの `odds-diagnostics` に新規追記します。実行別の履歴は上書き・削除せず、最新値の索引だけを更新します。失敗時は直前の成功値・元の観測時刻を保ち、空のページを公開しません。Supabaseへの追加保存、原本HTMLの保存、既存データの削除は行いません。コメントは従来のSupabaseを使うため、同じレースの既存コメントを共有します。

`site/` は検証済み表示データ、`public/` はGitHub Pages向けの生成結果です。`scripts/export_pages.py` はプロジェクト名を含むパスと通常の公式リンクへ変換し、出走データは変更しません。公開前にレイアウトのDOM、全車番ペア、着順リンクを確認し、公開後は認証情報なしでHTTPとファイル内容を照合します。

10月25日以降のスマートフォン表示は、最初の1.12倍からさらに12%大きい1.2544倍にしています。ブラウザーの初期ズームは標準に戻し、レイアウトを拡大して、横移動をページ全体にまとめます。表の内部との二重スクロールを避け、ピンチ拡大や左右への移動を妨げません。

```sh
python3 -m unittest discover -s tests -v
python3 scripts/export_pages.py
```
