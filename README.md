# keirin-lineup2

日程カレンダー担当への保存先・自動公開・日別直リンクの引き継ぎは [CALENDAR_HANDOFF.md](CALENDAR_HANDOFF.md) にまとめています。カレンダーの原稿は `site/calendar/`、公開用の日付一覧は `/keirin-lineup2/calendar/dates.json` です。

公開先は https://itaingtr.github.io/keirin-lineup2/ です。GPTログインは不要で、`line20261025.html` のような日付ページも同じ場所に置きます。トップと最新日付ページのHTMLは同一です。

誰か1人の期別を押すと、そのレース全員の期別の真下に県名の先頭2文字と年齢を表示し、もう一度どの期別を押しても全員分を閉じます。開閉は表示だけの操作です。「更新」「トップ」の横の「日程」は /keirin-lineup2/calendar/index.html へ移動します。カレンダー本体は別作業です。着順の左端はあがりタイムの十の位に合わせ、選手幅やライン間隔は維持します。

11月4日以降はS回数0を空欄にし、以前の着順・S・H・B・赤い調子を左詰めで続けて表示します。11月3日以降は期別・S回数・B数の順です。以前のあがりタイムは8pxへ小さくし、調子の数字はプラスもマイナスも赤の8px・通常の太さで表示します。B回数も太字を外し、着順横のBは8pxのまま通常の太さにします。並びの幅とライン間隔は維持します。

並びの選手幅とライン間隔は旧ページの設定を維持します。同じライン内は詰め、単騎も一つの独立したラインとして表示します。着順横の調子の表示で並びの幅を広げることはありません。

11月2日以降は、赤「映像」・緑「結果」・青「ライブ」の順です。映像とライブは楽天Kドリームスへ移動し、結果も当面は楽天の該当レースを開きます。映像のパソコン用750×470ウィンドウとスマートフォンの同じタブでの移動は維持します。

車番を押すと、その選手の調子を1→2→3→4→5→-2→-1→0→1の順に変更できます。11月3日以降はプラス・マイナスともに赤で、5が一番よい評価です。0と未評価は当日も翌日以降も空欄です。0は表示を消した状態として保存するので、以前の数字が戻ることはありません。合言葉で一度ログインすると同じブラウザでログイン状態を保持し、投稿と調子の入力ができます。評価は皆で共有し、今日の数字を今場所成績の下に表示します。翌日からは選手IDとレースIDで照合し、以前の着順の横に同じ色の数字を表示します。車番の変更には影響されません。

評価は既存の投稿用保存先へ専用キーで小さな記録を追記します。連打はまとめて保存し、過去の記録・通常のコメントは上書きも削除もしません。読み直した時と表示中の約30秒ごとに共有値を確認します。評価のために翌日分を複製保存することもありません。

10月30日以降の予想印は、車番・選手名・期別を照合した楽天Kドリームスの掲載印です。レース名のリンクも楽天へ移動します。画面の旧サービス名とAI印の補助表示を外し、既存の選手成績・並び・オッズの取得元記録は維持します。印は表示用の項目だけを実行別に追記し、翌日分の自動作成にも引き継ぎます。

11月4日以降の新しい出走表・並び・成績・予想印・選手ID・二車単は、楽天Kドリームスと競輪公式のKEIRIN.JPから実際に取得します。出走表・並び・成績集計・印・二車単は楽天、選手ID・今場所の着順・あがり・H/BはKEIRIN.JPです。前走のSは楽天の結果とレース・車番・選手・着順・タイムを照合して補います。稼働する収集処理ではウィンチケットを使用しません。従来の保存データや過去ページは変更せず、新しい楽天オッズは `fallback/kdreams/exacta` に分けます。オッズパークはスマホ版・PC版ともにActionsからHTTP403で取得できず、ユーザー指定によりKEIRIN.JPを利用します。H・S・Bを相互に推測して埋めることはありません。

`.github/workflows/update.yml` が承認不要で実行します。日本時間21:00・23:30に翌日分の出走表を取得・検証して公開し、当日の08:00〜20:30は15分間隔（08:00、08:15、…、20:30の1日51回）でオッズを取得します。取得できた最新オッズは表示用の最新値に上書き反映します。GitHubの実行開始は遅れる場合があり、予定された最終20:30の実行は遅延が1時間以内なら受け付けます。手動実行の `publish` は保存済みデータの公開（初回だけ現在日の取得元を切替）、`cards` は翌日分の取得、`odds` は当日分の取得です。

一時的な取得元の404・サーバーエラー・通信エラーは2秒後・5秒後に再試行し、最大3回で止めます。出走選手未確定・検証失敗なら公開中のページを維持し、夜の次回取得で確認します。23:30の起動が日付をまたいでも、取得対象をさらに翌日へずらしません。

表示用データは同じリポジトリの `odds-diagnostics` に新規追記します。実行別の履歴は上書き・削除せず、最新値の索引だけを更新します。失敗時は直前の成功値・元の観測時刻を保ち、空のページを公開しません。Supabaseへの追加保存、原本HTMLの保存、既存データの削除は行いません。コメントは従来のSupabaseを使うため、同じレースの既存コメントを共有します。

`site/` は検証済み表示データ、`public/` はGitHub Pages向けの生成結果です。`scripts/export_pages.py` はプロジェクト名を含むパスと通常の公式リンクへ変換し、出走データは変更しません。公開前にレイアウトのDOM、全車番ペア、着順リンクを確認し、公開後は認証情報なしでHTTPとファイル内容を照合します。

10月25日以降のスマートフォン表示は、最初の1.12倍からさらに12%大きい1.2544倍にしています。ブラウザーの初期ズームは標準に戻し、レイアウトを拡大して、横移動をページ全体にまとめます。表の内部との二重スクロールを避け、ピンチ拡大や左右への移動を妨げません。

```sh
python3 -m unittest discover -s tests -v
python3 scripts/export_pages.py
```
